# Torque Check

Crie um aplicativo web responsivo, pensado principalmente para ser usado pelo celular, chamado Mecânica Alto Torque — Check-in de Veículos.



O objetivo é permitir que uma oficina registre a entrada e saída dos veículos, faça registro fotográfico completo, marque avarias, registre os serviços realizados e peças trocadas, colete a assinatura do cliente na tela e gere um PDF profissional de todo o atendimento.

OBJETIVO PRINCIPAL



O aplicativo deve ser extremamente simples e rápido para o mecânico utilizar durante a entrada de um veículo.



A tela inicial deve ter botões grandes:



1. NOVA ENTRADA

2. VEÍCULOS / HISTÓRICO

3. ATENDIMENTOS EM ANDAMENTO

4. BUSCAR PELA PLACA



Não criar uma interface excessivamente complexa.



CADASTRO DO CLIENTE



Ao criar uma nova entrada, solicitar:



- Nome do cliente



DADOS DO VEÍCULO



Solicitar:



- Placa

- Ano

- Quilometragem



Depois permitir iniciar o checklist.



CHECKLIST FOTOGRÁFICO DE ENTRADA



Criar uma sequência organizada de fotografias.



Fotos externas:



- Frente

- Traseira

- Lateral esquerda

- Lateral direita

- Teto



Fotos das rodas:



- Roda dianteira esquerda

- Roda dianteira direita

- Roda traseira esquerda

- Roda traseira direita



Fotos internas:



- Banco dianteiro

- Banco traseiro

- Painel

- Porta-malas



Fotos mecânicas:



- Motor

- Bateria

- Outros detalhes



Cada item deve ter um botão grande para:

"TIRAR FOTO"



O aplicativo deve permitir tirar a foto diretamente pela câmera do celular ou selecionar uma foto da galeria.



Mostrar claramente quais fotos já foram feitas e quais ainda faltam.



Permitir adicionar fotos extras quando necessário.



REGISTRO DE AVARIAS



Criar uma área chamada:



"AVARIAS EXISTENTES"



Mostrar uma representação visual de um veículo visto de cima/lados, adequada para marcar danos.



Permitir que o usuário toque no local da carroceria onde existe uma avaria.



Ao adicionar uma avaria, permitir escolher:



- Risco

- Amassado

- Trinca

- Quebra

- Peça danificada

- Peça faltando

- Outro



Permitir adicionar uma descrição.



Exemplo:

"Risco profundo na porta dianteira direita."



Também permitir adicionar uma foto específica daquela avaria.



As marcações devem aparecer no desenho do veículo e também no relatório PDF.



CHECKLIST DE ENTRADA



Criar uma etapa chamada:



"CHECKLIST DE ENTRADA"



Permitir registrar itens importantes como:



- Estado geral da carroceria

- Vidros

- Espelhos

- Faróis

- Lanternas

- Pneus

- Rodas

- Bancos

- Tapetes

- Painel

- Som/multimídia

- Chaves

- Combustível

- Objetos deixados dentro do veículo



Cada item pode ter:



- OK

- Com avaria

- Não verificado

- Observação



SERVIÇO



Depois da entrada, criar uma área:



"SERVIÇO"



Campos:



- Reclamação do cliente

- Diagnóstico encontrado

- Serviços realizados

- Observações do mecânico



PEÇAS TROCADAS



Criar uma área:



"PEÇAS TROCADAS"



Permitir adicionar várias peças.



Cada peça deve possuir:



- Nome da peça

- Marca

- Quantidade

- Observação



Exemplo:



Peça: Kit embreagem

Marca: Luk

Quantidade: 1

Observação: Substituído por desgaste.



Também permitir registrar:



"PEÇAS RECOMENDADAS"



para peças que foram identificadas como necessárias, mas não foram trocadas naquele atendimento.



PEÇA ANTIGA



Para cada peça trocada, permitir selecionar:



- Peça antiga entregue ao cliente

- Peça antiga ficou na oficina

- Peça antiga descartada

- Não informado



FOTOS DO SERVIÇO



Permitir adicionar fotos durante o reparo.



Exemplos:



- Peça antiga

- Peça nova

- Componente danificado

- Serviço realizado

- Motor desmontado

- Resultado do reparo



CHECKLIST DE SAÍDA



Criar uma etapa separada chamada:



"CHECKLIST DE SAÍDA"



Permitir registrar novamente o estado do veículo.



Mostrar as informações principais da entrada para comparação.



Permitir novas fotos de saída.



Registrar:



- Quilometragem de saída

- Estado geral

- Observações

- Serviços concluídos

- Pendências

- Recomendações



ASSINATURA DO CLIENTE



Criar uma área:



"CONFIRMAÇÃO DO CLIENTE"



O cliente deverá conseguir assinar diretamente na tela do celular usando o dedo.



Mostrar antes da assinatura:



"Declaro que conferi as condições do veículo registradas neste checklist e estou ciente das informações apresentadas."



Ter os botões:



- LIMPAR ASSINATURA

- ASSINAR



Salvar a assinatura junto ao atendimento.

HISTÓRICO



Criar uma área:



"HISTÓRICO DE VEÍCULOS"



Permitir pesquisar pela:



- Placa

- Nome do cliente



Ao abrir um veículo, mostrar todos os atendimentos anteriores.



Exemplo:



ABC1D23

2026 — Troca de embreagem

2026 — Revisão

2027 — Freios



Cada atendimento deve poder ser aberto novamente para consultar fotos, avarias, peças e PDF.



STATUS DO ATENDIMENTO



Cada atendimento deve possuir um status:



- Entrada realizada

- Em diagnóstico

- Em serviço

- Aguardando peça

- Aguardando aprovação

- Serviço concluído

- Aguardando retirada

- Entregue



BANCO DE DADOS



Criar banco de dados persistente para:



- Clientes

- Veículos

- Atendimentos

- Fotos

- Avarias

- Checklists

- Serviços

- Peças

- Peças recomendadas

- Assinaturas

- PDFs



As fotos e arquivos devem ser armazenados de forma persistente e relacionados ao atendimento correto.



Não utilizar dados fictícios como solução final.



SEGURANÇA



Criar autenticação para que somente usuários autorizados da Mecânica Alto Torque possam acessar os dados.



Os dados de um atendimento não podem ficar públicos.



Configurar corretamente as permissões do banco de dados e armazenamento.



EXPERIÊNCIA NO CELULAR



O aplicativo será usado principalmente em celulares Android.



Os botões devem ser grandes.



A câmera deve ser facilmente acessível.



Evitar digitação desnecessária.



Usar menus simples.



Depois de tirar uma foto, voltar automaticamente para a lista de fotos.



Mostrar progresso, por exemplo:



"Fotos: 8 de 15"



REGRAS IMPORTANTES



Não criar apenas uma demonstração visual.



Quero um aplicativo funcional, com banco de dados, armazenamento das fotos, autenticação, cadastro, histórico e geração real de PDF.



Não apagar funcionalidades já criadas quando fizer alterações futuras.



Antes de implementar, analise toda esta especificação e organize a arquitetura do aplicativo.



Comece criando a estrutura principal, banco de dados e telas do aplicativo.



Depois implemente o fluxo completo:



NOVA ENTRADA → CLIENTE → VEÍCULO → FOTOS → AVARIAS → CHECKLIST → SERVIÇO → PEÇAS → SAÍDA → ASSINATURA → PDF → HISTÓRICO.



Priorize simplicidade, velocidade e facilidade de uso no celular.
